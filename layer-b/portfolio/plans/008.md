### Import and review requirements

**Acceptance:** Current source content is readable, provenance is recorded, and requirements and missing sections are documented.

### Confirm scope and accountability

Define one bounded use case: Compare a documented policy-analysis workflow with a simpler baseline

**Acceptance:** Owner, affected users, jurisdiction, exclusions, user actions and acceptance criteria are recorded; scope is checked against the source.

### Define the input contract

Specify fields, identifiers, provenance and quality rules for: Policy questions, alternatives, assumptions, model outputs and reviewer corrections

**Acceptance:** Document valid and invalid example records, access and retention limits, missing-value handling and source freshness.

### Establish baseline and safeguards

Track factual error rate and review time; countercheck unsupported claims

**Acceptance:** Baseline and counter-metric definitions include units, denominator, time window, missingness and uncertainty; unknown values remain null.

### Implement the bounded workflow

Deliver an executable workflow for the confirmed use case. Apply: Retain human review and disclose model limitations and uncertainty

**Acceptance:** Users can complete the documented use case with persisted records, input validation, error handling, accessible interactions and traceable corrections.

### Verify behavior and failure paths

Test the agreed workflow using authorized examples or explicitly labeled synthetic fixtures.

**Acceptance:** Record reproducible test commands and results covering the main workflow, malformed input, missing evidence, source changes and recovery; verify the counter-metric.

### Record independent acceptance and limitations

Have qualified reviewers compare the delivered workflow with the confirmed requirements.

**Acceptance:** Record reviewer identity, evidence references, unresolved findings, limitations and a support/maintenance owner. Software completion does not authorize live government action.

### Prepare reproducible handoff

Document setup, dependency versions, backup/restore, operating boundaries and rollback.

**Acceptance:** A second person can reproduce the accepted workflow and restore a workspace from a tested backup. Any live deployment decision is separately documented.
