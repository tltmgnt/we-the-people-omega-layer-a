# Layer B — proposed 90-day implementation roadmap

Day ranges are relative to an authorized start; no calendar commitment or participating
institution is implied. The local starter package does not begin a real pilot.

| Window | Focus | Deliverables and acceptance evidence |
| --- | --- | --- |
| Days 1–30 | Map | One bounded function, accountable owner, authority questions, lifecycle/dependencies, data inventory, metric/counter-metric definitions and privacy/records/security limits |
| Days 31–60 | Diagnose | Workload and resource baseline, reconciled records where appropriate, competing hypotheses, data-quality assessment and bounded remedies with owners |
| Days 61–90 | Test | Authorized pilot or controlled simulation, comparison with baseline and safeguards, legal/access/continuity review, published limitations, durable owner/funding/monitoring plan |

## Recommended first pilot

Proposed **California Public-Service Operations Observatory**: choose one permit process,
records request or maintenance workflow. This name is a project proposal, not an established
institution or authorized observatory. Use lawfully accessible data, explicit measures
and proportionate access. Do not create an unrestricted centralized government database
or assume one agency can access another's records.

The included [permit example](examples/permit/README.md) is a synthetic preparation exercise.
No live California institution or actual permit performance is assessed.

## Starter package release criteria

- Owner chooses the exact repository name, visibility and authorized license.
- Qualified reviewers examine domain and gate content and record limitations.
- Tests, examples and local documentation links pass on the intended commit.
- Unresolved authority, data access, reviewer assignments and operational gaps remain visible.
- Sources are checked for current applicability; synthetic data is clearly labeled.
- Release notes distinguish implementation, proposed methods and future work.

No tag or publication is authorized merely by this checklist. Start with 0.1.0-alpha
as a preparation milestone; schema version 0.1.0 is independently versioned.

## Subsequent work

Agree a real Layer A review for the selected proposal, Layer C outcome definitions and
Layer D evidence contracts with affected maintainers. Define historical transitions,
authenticated review provenance, remote-reference freshness and incident/correction handling.
Test measurement reliability and causal explanations before introducing rankings or composite
TGA/DTI scores. Operational adoption, personnel actions and purchases are outside this starter.

## Five-layer and portfolio coordination

Agree Layer A safeguards, B operations, C human outcomes, D evidence/validation and E transition/adoption roles for the chosen pilot. Use the [portfolio register](portfolio/README.md) to confirm project identity and unresolved scope; no project is authorized by inclusion. Submit the [collaboration brief](docs/Collaboration/concept-and-pilot.md) through an institution-selected process only after outreach is separately requested.
