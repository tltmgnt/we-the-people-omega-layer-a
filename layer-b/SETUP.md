# Repository setup and acceptance

## Intended repository

Suggested name: we-the-people-omega-layer-b
Suggested description: Government operations framework for institutional capacity, public finance, procurement, civil service, records and essential services.

No Layer B repository was available through the connected GitHub account when this package
was prepared. No repository was created, remote configured, branch pushed or release published.

## Import

1. Create or identify the intended repository and choose its visibility explicitly.
2. Extract this ZIP and place the contents of its we-the-people-omega-layer-b directory
   at the repository root, preserving .github and .gitignore.
3. Install requirements-dev.txt in Python 3.12 and run README validation commands.
4. Open one initial-preparation PR; review the diff, synthetic records, source provenance
   and current limitations before merging.
5. Resolve licensing and qualified review before inviting public reuse or claiming readiness.

If using git locally, initialize the extracted directory, review the files, commit and add
the actual repository URL as the remote. Do not paste a guessed remote or commit credentials.

## Acceptance checklist

- [ ] Exact repository and visibility chosen by owner.
- [ ] Code/docs/Layer A snapshot license coverage explicitly authorized.
- [ ] Six domains and thirteen supplied framework sections mapped in ORIGIN.md.
- [ ] Domain, financial terminology and gate content reviewed by qualified people.
- [ ] Tests and CI pass on the actual target commit.
- [ ] Permit example remains synthetic, unmeasured and blocked.
- [ ] No protected institutional/personnel/vendor records or credentials included.
- [ ] README, roadmap and changelog reflect delivered rather than assumed capabilities.
- [ ] Release, remote access and consequential-action roles remain separately authorized.

A prepared ZIP is not a published repository, a jurisdiction-specific compliance framework
or a deployed agent system. There are no live data connectors or operational permissions.
