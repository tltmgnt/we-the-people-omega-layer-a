# DTI Ω — temporal capacity and administrative burden

Measure the whole public-service journey. A faster internal process may merely transfer
effort to residents or another agency.

| Component | Definition |
| --- | --- |
| Elapsed time | Time between explicitly defined start/end events |
| Active staff time | Staff effort performing work |
| Active public time | Preparation, submission, travel, in-person waiting, response and correction effort |
| Queue time | Waiting for the next required action |
| Coordination time | Obtaining information and resolving handoffs |
| Rework | Effort from errors, duplication or avoidable correction |
| Recovery time | Time to restore service after disruption |

The proposed service-friction profile is:

`T_service = (T_e, T_s, T_p, T_q, T_r, T_c)`

These components represent elapsed time, staff effort, public effort, queue time, rework
and coordination burden. Recovery is separately recorded for disruption scenarios.
Elapsed time and effort are different quantities; components can overlap or run in parallel.
Do not add them into a composite without a validated measurement model and explicit weights.

## Measurement plan

Define boundary events, clock/calendar and time zone, business-time versus calendar-time
rules, paused cases, open/censored cases, case complexity and population exclusions.
Report sample size, missing data and uncertainty. Capture public effort through an
authorized proportionate method; absence of a complaint is not absence of burden.

DTI Ω is a proposed project method. Keep dimensions separate until measurement properties,
reliability and decision usefulness have been tested. Compare speed with access, safety,
decision accuracy, appeals, abandonment and rework.
